# Repository audit: host correctness, tests and limits

This audit covers the host code in `src/host/`, its tests and its
documentation, starting from commit `7928988`. It separates measured facts
from assumptions. [meas.] is measured here, [doc.] is from vendor
documentation, [ref] is from another project's source (read only), and
[hyp.] is not verified.

## 2. Defects found and fixed

All of these are in `src/host/`. Each one has a test that failed before
the fix or that covers the new behaviour.

| # | Where | Defect | Fix | Test |
|---|---|---|---|---|
| 1 | `tm_vfs.c` | A listing's virtual entries were capped at 16. Up to 8 mounts plus 16 host DLLs are possible, so entries could be dropped silently | the capacity is `TM_MAX_MOUNTS + TM_LOADER_MAX_DLLS` | `test_vfs_audit`: a directory with 7 mounts and 16 host DLLs lists 2 + 7 + 16 entries |
| 2 | `tm_vfs.c` | `FindFirstFileA` used `calloc` and `realloc` results unchecked (a NULL dereference on failure) | each failure returns `INVALID_HANDLE_VALUE` with `ERROR_NOT_ENOUGH_MEMORY`, and frees what was allocated | `test_vfs_audit`: failure injected at each allocation |
| 3 | `tm_vfs.c` | a full handle table returned `INVALID_HANDLE_VALUE` with no error set | `ERROR_TOO_MANY_OPEN_FILES` | `test_vfs_audit`: the table filled |
| 4 | `tm_vfs.c` | `GetFileAttributesA` (win32hle's) gave `ERROR_FILE_NOT_FOUND` for every failure | 2 or 3 by whether the parent directory exists; 206 for `MAX_PATH` or more; 3 for NULL and `""` | `test_vfs_audit` |
| 5 | win32hle `FindClose` | closed any handle type, and set no error on failure | `tm:FindClose` closes search handles only; for any other handle it returns FALSE with `ERROR_INVALID_HANDLE` and leaves it open | `test_vfs_audit` |
| 6 | `tm_vfs.c` | the wildcard matcher did not follow the DOS rules (`a??` did not match `a`; `.*`, a trailing `.`) | the mask is rewritten into NT's DOS wildcards and matched as `FsRtlIsNameInExpression` does (IMPORTS.md) | 36 mask cases |
| 7 | `tm_vfs.c` | names were not limited to `MAX_PATH` | 260 characters or more: `ERROR_FILENAME_EXCED_RANGE` | `test_vfs_audit` |
| 8 | `tm_loader.c` | host DLL handles (`0x7D000000 + 0x10000 * i`) lay inside the range where guest "anywhere" allocations go (`0x10000000`–`0x7F000000`), so a heap block could share an address with a module handle | the 1 MB range is reserved when the first host DLL is registered and left `PROT_NONE` | `test_loader_audit`: the range cannot be reserved, and reading it faults |
| 9 | `tm_loader.c` | `tm_loader_add` ignored a 17th DLL and duplicate names without a word | it returns 0 with a message | `test_vfs_audit`, `test_loader_audit` |
| 10 | `tm_vfs.c` | a mount's last component was truncated at 63 characters | such a mount is refused | `test_vfs_audit` |
| 11 | `tm_vfs.c` | each search copied about 106 KB of virtual entries | the search keeps only the entries it lists | covered by the listing tests |
| 12 | `tm_imports.c` | `FindClose` was listed as win32hle's although the host now answers it | listed as implemented; the committed boundary trace is regenerated (the statuses in it also predated the file-system work: the call counts are unchanged) | `tests/m3_boundary.py` |

No game-visible behaviour on the measured path changed. The M2 and M3
results are identical before and after; only the import statuses in the
trace differ.

## 3. Areas checked without a defect

- **Search lifecycle.** `FindNextFileA` after the end keeps the handle
  valid. `FindClose` twice fails the second time. A NULL buffer gives 87.
  [meas.]
- **Mount boundaries.** `C:\WINDOWS_OLD` is not inside `C:\WINDOWS`.
  Repeated and mixed separators, `.` and `..` above the mount, relative
  names, `C:name` and `\name` all resolve inside or outside the mount
  correctly. [meas.]
- **Loader.** Stale handles (A unloaded, then B loaded) fail with
  `ERROR_MOD_NOT_FOUND` and do not touch B. Handles off the 64 KB step, or
  in an empty slot, fail the same way. Reference counts never go below
  zero, and a reload after unload gives the same handle. Ordinal and NULL
  names give `ERROR_PROC_NOT_FOUND`. Export addresses are shim VAs. [meas.]
- **Guest pointers.** `hle_va` stops the run on a host pointer. The
  DirectInput 8 object and its vtable are guest memory, and all 11 vtable
  slots are dispatchable shims. [meas.]
- **Concurrency.** Every shim, and so every file-system and loader call,
  runs under win32hle's machine lock. Mounts and host DLLs are registered
  at start-up, before guest code runs, and are read-only after that. There
  is no assertion API for "lock held", so this is documented, not
  enforced. [ref, meas.]
- **ASan.** `test_vfs_audit`, `test_vfs`, `test_loader` and `test_sysroot`
  built with `-fsanitize=address,undefined`: no reports. [meas.]

## 4. Remaining risks (not fixed)

| Risk | Where | Effect | Reached by the game? |
|---|---|---|---|
| `FreeLibrary` returns TRUE for any handle that is not a host DLL | win32hle | a stale or wrong handle is not reported | no case seen |
| `GetProcAddress` with an invalid module gives 127, not 126 | win32hle (non-host modules) | wrong error code | no case seen |
| win32hle's system-module range at `0x7E000000 + 0x10000 * k` is not reserved | win32hle | a guest allocation could in principle land on a module handle, the same defect as #8 | [hyp.] low: allocations grow from `0x10000000` |
| `CloseHandle` accepts a search handle | win32hle | Windows refuses it | no |
| a trailing `\` after a file name | `hle_path.c` | not checked against Windows | no |
| no 8.3 names (`cAlternateFileName` empty) | `tm_vfs.c` | a game that relies on short names would fail | no |
| `IsBadReadPtr`, `IsBadWritePtr`, `IsBadCodePtr` only check `< 0x10000` | win32hle | a probe of unmapped memory says "good" | not called on the measured path |
| `RtlUnwind` does nothing; no C++ EH dispatch | win32hle; the lift | a guest throw stops the run (docs/EXCEPTIONS.md) | no throw taken so far |
| a second `CoInitialize` returns `S_OK` instead of `S_FALSE` | win32hle | harmless for the probe, which tests `>= 0` | yes, twice |

## 5. Coverage gaps

- **No Windows comparison.** None of the error codes above has been
  checked on real Windows. They follow the documentation and, where it is
  silent, Wine's behaviour.
- **No multi-threaded test.** The concurrency claim rests on the machine
  lock and is not exercised by a test.
- **The exit-path fault** in `sub_00936350` is not explained: whether
  Windows takes the same fault there.
- **Wide-character file APIs** (`CreateFileW`, `FindFirstFileW`, ...) are
  stubs and untested. They have not been called so far.
- **The lifted code itself** is tested only through the M2 and M3 runs.

## 6. Exceptions (B4)

docs/EXCEPTIONS.md has the evidence. In short: 5,646 functions have MSVC
C++ EH frames and 1,031 contain a throw. The measured start-up run enters
186 of the former and takes no throw. The lift keeps the `fs:[0]` chain,
but it has no catch landing pads. A working implementation needs a re-lift
with pcrecomp's EH pass and a dispatcher ported to win32hle. None is added
now.

## 7. DirectShow (the current boundary)

docs/DIRECTSHOW-STARTUP.md has the probe's calls, read from the
instructions, and the run's results. The probe creates the threaded filter
graph, the capture graph builder and the **ASF writer**. Playback (the ASF
**reader**) is a different function and is not reached. The document also
sets out the instrumentation design. Nothing is implemented.

## 8. Android readiness

| Level | State |
|---|---|
| 1. Theoretically portable: no x86-only code, no Windows API, no inline asm in the host and the lifted C; pointers are guest VAs | **reached**: the host is C11 and POSIX with SDL2; the lifted code is portable C; based memory keeps the guest within its 4 GB [meas. on x86-64] |
| 2. Compiles for arm64 Linux | not tried: no arm64 toolchain or machine here |
| 3. Runs to `WinMain` on arm64 Linux | not tried |
| 4. Builds with the Android NDK and runs as a console binary over `adb shell` | not tried: no NDK and no device |
| 5. An APK: data import, a surface, the Activity lifecycle | not started (M7) |

Known questions for levels 2–4: the 4 GB `PROT_NONE` reservation must fit
the device's address space and overcommit policy, and on Android the
lifted image is a 690 MB binary. [hyp.] On arm64 Linux both should be
fine. On Android, the reservation may be limited by `vm.overcommit` and
the memory cgroup, and a binary that size must be extracted rather than
mapped from the APK.

## 9. Open decisions

1. **DirectShow at start-up.** The probe passes only with a real filter
   graph, capture graph builder and ASF writer filter. Either start-up
   waits until film export works, or these three objects are implemented
   for what they claim (graph bookkeeping and a writer filter with no
   connected pins), and encoding comes later.
2. **Where to fix win32hle defects** (section 4): in host overrides, as
   for `FindClose`, or as patches to the pcrecomp copy in
   `patches/pcrecomp/`.
3. **When to re-lift with EH landing pads.** It changes all of `gen/` and
   costs a full rebuild of about 22 minutes. Doing it before the first
   throw is reached keeps one baseline instead of two.
